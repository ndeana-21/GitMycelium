# Архитектура

## Цели и ограничения

1. Нативный бинарник на C++/Qt 6. Без Electron, без веб-вьюхи.
2. Огромные монорепозитории: ~1M коммитов, тысячи веток, partial clone.
3. Сборка: **macOS arm64** (Apple Silicon, единственный mac-таргет) и
   **Linux x86_64**.
4. Приоритет №1 по фичам — merge-конфликты и ветки; архитектура это отражает.
5. Личный проект / возможно OSS → LGPL Qt и GPL-зависимости допустимы, но
   фиксируем осознанно.

## Решение №1: git-бэкенд — libgit2 + git CLI

Rust отпал вместе с выбором C++ → `gix` вне игры. Остаются два инструмента, оба
на C/C++:

| Возможность | libgit2 1.9.7 (C API) | `git` CLI 2.55 |
|:--|:--:|:--:|
| чтение истории, revwalk, commit-graph | ✅ | ✅ |
| status / diff / blame | ✅ | ✅ |
| merge (3-way, конфликты, стадии 1/2/3) | ✅ (`git_merge`, `git_merge_file`, conflict iterator) | ✅ |
| rebase / cherry-pick / revert | ✅ | ✅ |
| stash, tags, worktree | ⚠️ частично | ✅ |
| checkout/switch/reset | ✅ | ✅ |
| partial clone / promisor | ❌ | ✅ |
| hooks, LFS | ⚠️ | ✅ |
| скорость на больших репах | хорошая, без процессов | своя |

**Решение:** тот же гибрид, но вместо gix — libgit2.

- **Основной путь → libgit2 (C API).** Чтение, diff, status, **merge и разбор
  конфликтов** (у неё есть итератор конфликтов, отдающий стиджи 1/2/3 —
  ancestor/ours/theirs), rebase, cherry-pick, checkout. Это один C-тулчейн рядом
  с Qt, без лишних процессов.
- **git CLI подпроцессом → там, где libgit2 слаб или не умеет:** partial clone /
  promisor-репозитории, hooks, LFS, некоторые тонкие работы с worktree,
  `merge-tree --write-tree` (предсказание конфликтов), `maintenance`/`gc`.
- **Детект promisor-репы:** если в конфиге есть `extensions.partialClone` или
  `.promisor` — на чтение идём через CLI (`git cat-file`, `git log`), libgit2 такую
  репу корректно не откроет. Это важный питфолл, закладываем явную проверку.

Обёртки: тонкий C++-слой `gk::git` (RAII над `git_*`, `std::expected`-подобные
ошибки, без исключений через границы), плюс `gk::cli` — типизированный запуск
`git` с разбором машинного вывода (`-z`, `--porcelain=v2`, `for-each-ref --format`).

### Питфолл: потокобезопасность libgit2

libgit2 не любит параллельные операции над одним репозиторием. Поэтому `RepoSession`
держит `QMutex` вокруг каждого вызова libgit2: одна дверь на репозиторий, длинные
чтения — на пуле потоков, результат возвращается queued-сигналом.

## Решение №2: UI — Qt 6

Выбор сделан Сэром: C++ + Qt 6. Внутри Qt — развилка Widgets vs Quick.

| | Qt Widgets | Qt Quick / QML |
|:--|:--|:--|
| Текстовый редактор | `QPlainTextEdit` + `QSyntaxHighlighter` — проверенно для больших текстов | `TextArea`/`TextEdit` слабее для кода |
| Списки 1M | `QAbstractItemModel` + `canFetchMore`/`fetchMore` (ленивая догрузка) + `QTreeView` — эталон | `ListView` с делегатами, тоже ок |
| Граф | кастомный `paintEvent`/делегат `QStyledItemDelegate`, либо `QGraphicsView` | кастомные QSG-ноды (больше работы) |
| Скорость разработки | быстрее для «IDE-класса» | лучше для анимаций/современного вида |

**Решение для v0: Qt Widgets.** Причины: готовый редактор кода и проверенная
ленивая модель для миллиона строк — ровно наши два узких места. QML можно ввести
позже для «хрома» (шапка, панели) через `QQuickWidget`, не переписывая ядро.

Редактор конфликтов: `QPlainTextEdit`-производный виджет (он оптимизирован под
большие тексты, хранит строки отдельно), синхронизация скролла между панелями,
подсветка через `QSyntaxHighlighter`. Опция ускорения — **QScintilla** (Scintilla),
но у неё **GPLv3**; для личного/OSS ок, фиксируем как осознанный выбор, вводим
только если штатного редактора не хватит.

## Решение №3: структура проекта (CMake)

```
gitmycelium/
  CMakeLists.txt
  cmake/            # флаги, поиск Qt6/libgit2
  src/
    core/           # домен: Oid, Ref, Commit, Diff, Conflict; парсеры без Qt
    git/            # обёртки libgit2 (RAII) + типизированные подпроцессы git
    repo/           # RepoSession — единственная дверь к git-состоянию; oplog
    graph/          # укладка DAG (GraphLayout), анимация — без Qt
    theme/          # палитра, глифы, встроенные SVG-иконки
    model/          # Qt-модели (CommitModel, RefModel, files/word-diff/pins)
    ui/             # виджеты, делегаты, диалоги, MainWindow
    app/            # main()
  tests/            # ctest-бинарники на настоящих git-репозиториях
  bench/            # бенчмарки на синтетике
  docs/
```

Правило: `core`/`git`/`graph` не знают про Qt. UI зависит от моделей, модели — от
домена. `RepoSession` — единственная дверь к git-состоянию.

## Потоки и конкурентность

- **GUI-поток** — только виджеты и ввод, никогда git.
- **`RepoSession`** — `QMutex` вокруг каждого вызова libgit2; длинные чтения идут на
  `QThreadPool` и возвращаются queued-сигналом.
- Общение — сигналы/слоты Qt, инкрементальные апдейты моделей.
- **Watcher файловой системы** (`QFileSystemWatcher` + git fsmonitor) → инвалидация
  status/моделей.

## Рендер графа (1M коммитов)

- **`CommitModel`** на `QAbstractItemModel` с **ленивой догрузкой**: `canFetchMore`/
  `fetchMore` тянут историю страницами, `QTreeView` виртуализирует сам.
- Граф рисуем в `QStyledItemDelegate::paint()` (линии/узлы/бейджи по данным
  колонки-графа) — дёшево, попадает в тот же вьюпорт. Для сложных merge-дуг —
  при необходимости `QGraphicsView` слоем.
- Укладка DAG (`src/graph`) — в фоне, инкрементально, кэш позиций по страницам.
- LOD при сильном zoom-out, настраиваемый потолок визуализации.

## Сборка и релиз

- **CMake** + `qt_add_executable`, `CMAKE_PREFIX_PATH` к Qt6, `pkg-config`/vcpkg для
  libgit2.
- CI-матрица: `macos-14` (arm64, Qt из онлайн-инсталлятора/aqt) и
  `ubuntu-24.04` (Qt6 + libgit2 из пакетов/`aqtinstall`).
- Артефакты: macOS — `.app` + `.dmg` (arm64; нотаризация — отдельная задача),
  Linux — AppImage или `.tar.gz`.
- Версионирование и упаковка зависимостей (Qt/libgit2) фиксируем на конкретных
  версиях, чтобы сборки воспроизводились.

## Лицензии (осознанно)

- **Qt 6 — LGPLv3.** Для личного/OSS нормально при динамической линковке и
  возможности замены Qt пользователем. Не статически линковать Qt без коммерческой
  лицензии.
- **libgit2 — GPLv2 с linking exception** (по сути пригодна для проприетарного и
  OSS использования, линкуется свободно).
- **QScintilla — GPLv3** (если введём). Держим как опцию, а не как дефолт.

## Риски

1. **libgit2 не умеет partial clone** — решено: promisor-репы читаем через CLI.
2. **Потокобезопасность libgit2** — решено: `RepoSession` сериализует вызовы мьютексом.
3. **Редактор конфликтов на 3-4 панели** — самый дорогой UI-кусок; `QPlainTextEdit`
   + синхроскролл, при упоре в качество — QScintilla.
4. **Сборка Qt на CI для arm-мака** — решается `aqtinstall`/онлайн-инсталлятором;
   фиксируем версию Qt.
5. **Производительность `QTreeView` на 1M** — ленивая модель + делегат; при упоре —
   свой виртуализированный вид.
